# Manual de uso do sistema Dom Gabriel

Rascunho em Markdown. A ideia é, mais para a frente, transformar estes capítulos em um manual completo (PDF ou documento) para entregar às pessoas de cada setor.

Cada capítulo explica **uma tela do sistema na prática**: para que serve, quem usa, como ler, o que fazer no dia a dia e o que fazer quando algo parece errado.

## Como escrever um capítulo (para quem for mexer neste manual)

- **Linguagem de quem usa a tela**, não de quem programou. Nada de nome de tabela, função ou migration no texto; isso fica no `HANDOFF.md`.
- **Estrutura de cada capítulo:** Para que serve · Quem usa · De onde vêm as informações · Como ler a tela · Rotina do dia a dia (por perfil) · Passo a passo das ações · O que fazer com cada alerta · Dúvidas comuns · O que ainda não existe.
- **O repositório é público.** Nada de valor financeiro da empresa, nome de cliente ou de funcionário. Use os cargos (vendedor, logística, gerente, direção).
- **Telas do vendedor ajudam a vender, não explicam conta.** Nada de comissão, margem ou formação de preço no texto que vai para o vendedor. Quando um assunto interessar só à direção, ponha num bloco marcado **[Direção]**, para ser retirado da versão do vendedor.
- **Quando a tela mudar, o capítulo muda junto.** Atualize o texto e a linha "Última revisão" no topo do capítulo.
- Conferir sempre no sistema antes de afirmar: o manual descreve o que a tela faz hoje, não o que se planejou.
